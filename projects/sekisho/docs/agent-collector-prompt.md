# 収集役エージェント用プロンプト（Cursor等）

クライアント／社内システムへの直接接続権限が無い環境では、**すでにアクセス権を持つ
エージェント（Cursor等）**にデータ収集を任せ、その出力（観測JSON）を関所へ取り込む。

以下をエージェントに渡すと、`docs/observation.example.json` と同じ形式のJSONを生成できる。
生成された `observations.json` を `npm run ingest -- observations.json` で取り込む。

---

```
あなたは週次のSRE運用データを集めるアシスタントです。
アクセスできる範囲で先週（月曜〜日曜）の以下の指標を集め、指定のJSON形式で出力してください。
取得できなかった項目は無理に埋めず省略し、その源の名前を missingSources に記載してください。
推測値は入れないこと。

【集める指標】
- GitHub: リリース数, デプロイ数, マージPR数, revert/ロールバックにつながった変更数(changeFail),
  変更量が大きいリリース数(bigBangReleases), PRのリードタイム平均(時間),
  問い合わせIssueの 新規/解決/未対応 件数, 最古の未対応の滞留日数,
  火消し対応の件数(インシデント/問い合わせ/トイル), 改善タスクの件数
- AWS CloudWatch: アラート発報数, インシデント数, 平均復旧時間(分), エラー率(%), 早期検知率(%)
- Snowflake: パイプライン成功率(%), データ鮮度遅延(分), 処理行数, 失敗ジョブ数

【出力形式】
docs/observation.example.json と同じJSON。project.key と project.name は対象システム名にすること。
```

---

この方式なら、関所アプリはクライアント側の権限を一切持たずに、収集役の出力を評価・保存・比較できる。
将来、直接接続の許可が下りたら `SEKISHO_MODE=live` でアダプタ経路に切り替えられる（出力先は同じ）。
